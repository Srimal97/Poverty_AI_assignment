# Demo video script (target 4 minutes)

Record the screen with the Streamlit app running (`streamlit run app/app.py`), with the notebook or report open in another tab.

| Time | On screen | What to say |
|---|---|---|
| 0:00-0:30 | Report title; district poverty chart (fig02) | "Sri Lanka's welfare programmes cannot verify income. In 2019, Samurdhi missed 59% of poor households. I built a proxy-means-test model on the DCS Household Income and Expenditure Survey 2019 (19,911 households) that predicts whether a household is below the official poverty line of Rs 6,966 per person, using only things a field officer can see." |
| 0:30-1:05 | Feature table; stack diagram (report section 3) | "93 verifiable features: location, members, the head's education, housing materials, 26 durable assets, land and access to services. Income, debt, Samurdhi receipt, ethnicity and religion are excluded. Splits are grouped by PSU and weighted by the survey design. I compared 17 models: the traditional OLS PMT, ten lecture algorithms, and five new ones (EBM, Extra Trees, Balanced RF, NGBoost and a LightGBM consumption regressor). My proposed model stacks seven of them with a survey-weighted logistic meta-learner." |
| 1:05-1:40 | CV dot plot (fig05); bootstrap table | "The stack is best: test ROC-AUC 0.908 and PR-AUC 0.588. It beats the existing OLS PMT significantly (+0.027 PR-AUC, confidence interval above zero). The strongest single learner is the new consumption regressor, which takes 42% of the meta-weight." |
| 1:40-2:50 | App: Assess a household; load the example; scroll the form; show the result | "This is the screener. I load a held-out test household from Gampaha: seven members, one bedroom, firewood, three asset types. The model says 65% probability of poverty, so it is flagged for field verification. The SHAP table explains why: household size, crowding and few assets raise the risk; living in Gampaha lowers it. The household really is poor, at Rs 5,957 per person." Then change cooking fuel to LP gas, add a fridge and a motorcycle, press Assess, and show the probability falling. |
| 2:50-3:15 | Sidebar policy switch; Batch scoring tab | "The officer can switch between minimising exclusion (86% of poor reached) and a balanced threshold. Batch scoring ranks a whole list of households from a CSV." |
| 3:15-3:50 | Model card tab; fairness chart (fig13); Samurdhi curve (fig14) | "At the same 21% coverage as Samurdhi, the model misses 23% of poor households instead of 59%. The fairness audit shows lower recall for the urban poor, and over-selection of estate households through sector proxies, so it is decision support only and must be retrained on post-crisis data." |
| 3:50-4:10 | GitHub repo: CI badge or Actions, Dockerfile, MLflow UI | "Everything is reproducible: Optuna tuning and all runs are tracked in MLflow, tests and a Docker build run in GitHub Actions, and the app deploys from the repository. Thank you." |
